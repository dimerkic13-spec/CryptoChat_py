# CryptoChat 0.2.5a — помощник КриптоПро (Python)

> **Что нового в 0.2.5a:** проанализированы все 38 вопросов и их ключевые слова, переработаны ключи
> у 26 вопросов, добавлены 13 групп синонимов, у каждого вопроса появились примеры формулировок
> (`examples`) для поиска по смыслу, контрольных запросов стало 152. Подробно: [CHANGES_0.2.5a.md](CHANGES_0.2.5a.md).
> История всех версий, от C# до Python: [HISTORY.md](HISTORY.md).

Консольный бот, который отвечает на вопросы по базе FAQ из JSON-файлов.
Ответы выдаются дословно из базы, без ИИ.

Используемые библиотеки:

| Библиотека | Для чего | Нужно ли ставить |
|---|---|---|
| `re` | разбиение текста на слова, стеммер, синонимы-фразы | встроена в Python |
| `sqlite3` | база бесед `logs/cryptochat.db` и статистика `--stats` | встроена в Python |
| `pymorphy3` | морфология: «рутокена» → «рутокен» | необязательно; без неё — простой стеммер |
| `RapidFuzz` | учёт опечаток: «рутокин» ≈ «рутокен» | необязательно; без неё — встроенный `difflib` |
| `sentence-transformers` + `PyTorch` | поиск по смыслу: «не могу зайти в аккаунт» → «Забыл логин/пароль от личного кабинета» | необязательно, большая установка (`requirements-semantic.txt`) |

Установить необязательные: `python -m pip install -r requirements.txt`.
Если RapidFuzz не устанавливается (для самых новых версий Python готовой сборки может ещё не быть),
поставьте только морфологию: `python -m pip install pymorphy3` — опечатки будет учитывать `difflib`.

## Требования

- Python 3.10 или новее (python.org → Downloads). При установке на Windows отметьте **Add python.exe to PATH**.

Проверка: `python --version`.

## Морфология (pymorphy3)

Установка (один раз, нужен интернет):

```powershell
python -m pip install -r requirements.txt
```

Режим задаётся в `content/config.json`:

```json
"text": { "morphology": "auto" }
```

| Значение | Что делает |
|---|---|
| `auto` | pymorphy3, если он установлен, иначе стеммер (по умолчанию в базе) |
| `pymorphy3` | только морфология; без библиотеки бот не запустится и скажет, что установить |
| `stemmer` | простой стеммер, как раньше |

При запуске бот пишет, какой режим работает. Для разового запуска в другом режиме:
`python run.py --morphology stemmer`.

Сравнить режимы на контрольных запросах:

```powershell
python run.py --compare
```

Команда покажет, сколько проверок прошло в каждом режиме и где результаты различаются
(с основами слов). По этому выводу подбираются ключевые слова и синонимы.

С морфологией ключевые слова тоже приводятся к начальной форме: «купил» и «купить» — одно и
то же слово. Если в вопросе есть оба, это предупреждение V008, и при загрузке остаётся один ключ
с большим весом.

## Поиск по смыслу (sentence-transformers на PyTorch)

Нейросетевая модель сравнивает смысл запроса с заголовками вопросов, поэтому находит нужный вопрос,
даже если общих слов нет. Ответ по-прежнему выдаётся дословно из базы: модель только выбирает вопрос.
Модель работает на этом компьютере, запросы никуда не отправляются.

**Установка** (лучше в отдельное окружение `.venv`, установка — сотни мегабайт):

```powershell
python -m pip install -r requirements-semantic.txt
python run.py --download-model
```

Вторая команда один раз скачивает модель (по умолчанию `cointegrated/rubert-tiny2`, ~120 МБ) в папку
`models` рядом с программой. Дальше интернет не нужен. Если для вашей версии Python PyTorch ещё не
выпущен, сделайте окружение на Python 3.13.

**Как считается оценка.** Для запроса считается похожесть (от −1 до 1) с каждым вопросом.

У многих моделей похожесть почти любых двух фраз на одну тему высокая (у `rubert-tiny2` — около 0.75–0.8),
поэтому по умолчанию используется **относительная** оценка (`"mode": "relative"`): насколько вопрос
выделяется на фоне остальных (z-оценка). Учитываются только `topK` самых похожих вопросов. Ниже `zLow` —
0, выше `zHigh` — `weight`, между ними — пропорционально. Если модели все вопросы кажутся одинаково
похожими, она ничего не добавляет и не «заливает» поиск лишними вариантами.

Итоговая оценка вопроса (`combine`): `or` — смысл усиливает ключи (ключи + смысл − ключи × смысл);
`max` — лучшее из двух.

**Запасное меню.** Если подходящих вопросов нет, бот не уходит сразу в меню тем, а предлагает
«Возможно, вы имели в виду…» (до 3 вариантов):
1. вопросы, которые по ключам почти дотянули до порога — оценка не ниже `dialog.suggestScore` (0.15);
2. самые похожие по смыслу вопросы, выделяющиеся на фоне остальных не меньше чем на `semantic.menuZ`.

Пункт `0` по-прежнему ведёт в техподдержку. Если предложить нечего — меню тем, как раньше.
Выбор темы или блока в меню — это навигация, а не неудачная попытка: такие шаги не считаются
в `escalateAfterSteps`, и бот всегда доводит до списка вопросов блока.

**Калибровка (28.10.2026, модель `rubert-tiny2`).** Настройки по умолчанию подобраны по выгрузке
`--semantic-dump` на 93 проверках и выбраны в устойчивой области (соседние значения дают тот же результат):

| | без модели | с моделью |
|---|---|---|
| контрольные запросы и заголовки | 83 из 83 | 83 из 83 |
| бот отвечает сразу, без переспроса | 38 | 56 |
| перефразы: правильный вопрос первый | 3 из 10 | 6 из 10 |
| перефразы: правильный вопрос в меню | 3 из 10 | 8 из 10 |

Модель сама по себе слабая (правильный вопрос первым у неё лишь в половине перефразов), поэтому она не
выбирает ответ одна, а усиливает ключи и подсказывает варианты. При смене модели настройки нужно подобрать
заново по новой выгрузке. Тест `CalibrationRegressionTests` проверяет, что правки не ухудшили результат.

Настройки в `content/config.json`:

```json
"semantic": {
  "enabled": true,
  "model": "cointegrated/rubert-tiny2",
  "cacheDir": "models",
  "device": "cpu",
  "localFilesOnly": false,
  "mode": "relative",
  "zLow": 0.0,
  "zHigh": 5.0,
  "topK": 3,
  "low": 0.55,
  "high": 0.9,
  "weight": 0.3,
  "combine": "or",
  "queryPrefix": "",
  "passagePrefix": "",
  "menuFallback": true,
  "menuZ": 1.5,
  "menuSize": 3
}
```

| Поле | Что значит |
|---|---|
| `enabled` | `false` — выключить |
| `model` | модель с Hugging Face; для русского подходят также `intfloat/multilingual-e5-small`, `deepvk/USER-base` |
| `cacheDir` | куда скачивается модель |
| `device` | `cpu` или `cuda` (видеокарта NVIDIA) |
| `localFilesOnly` | `true` — не обращаться в интернет, брать модель только из `cacheDir` |
| `mode` | `relative` — на фоне остальных вопросов (по умолчанию); `absolute` — по самой похожести |
| `zLow`, `zHigh`, `topK` | для `relative`: насколько вопрос должен выделяться и сколько лучших учитывать |
| `low`, `high` | для `absolute`: границы похожести |
| `weight` | максимальная оценка от смысла: при 0.5 модель только предлагает вариант, при 0.8 может ответить сразу (порог 0.6) |
| `combine` | `or` (по умолчанию) или `max` |
| `menuFallback`, `menuZ`, `menuSize` | запасное меню похожих по смыслу вопросов, когда ключи ничего не нашли |
| `queryPrefix`, `passagePrefix` | для моделей семейства e5 и `deepvk/USER-base`: `"query: "` и `"passage: "` |

**Настройка порогов.** Пороги `low`/`high` зависят от модели, их нужно подобрать на ваших запросах:

```powershell
python run.py --compare-semantic
```

Команда прогонит контрольные запросы, заголовки и перефразы из `content/paraphrases.json` с моделью и без неё
и покажет, где модель помогла, а где помешала, с похожестью для каждого запроса.

Для точной настройки выгрузите все оценки:

```powershell
python run.py --semantic-dump
```

Команда сохранит `semantic_dump.json`: для каждого контрольного запроса — оценки по ключам и похожесть
по смыслу для всех вопросов, и покажет сводку (как часто правильный вопрос первый по смыслу и по ключам).
По этому файлу подбираются `mode`, `zLow`, `zHigh`, `weight` и `combine`.

**Другие формулировки вопроса.** У вопроса можно указать поле `examples` — модель будет сравнивать
запрос и с ними:

```json
"examples": ["не могу зайти в аккаунт", "не помню пароль от кабинета"]
```

Если библиотека не установлена или модель не загрузилась, бот пишет об этом при запуске и работает
по ключам, как раньше. В отладке (`/отладка вкл`) видно: `[ключи 0.00, смысл: похожесть 0.71]`.

## Учёт опечаток (RapidFuzz)

Если слово запроса не совпало с ключом ни точно, ни по началу, бот сравнивает их нечётко.
`«забыл пароль от рутокина»` находит вопрос про пин-код, `«нужен дубликт лицензии»` — про дубликат.
Ключ, совпавший с опечаткой, даёт 80 % своего веса, чтобы точное совпадение всегда было весомее.

Настройки в `content/config.json`:

```json
"fuzzy": { "enabled": true, "threshold": 85, "minLength": 5, "weight": 0.8 }
```

| Поле | Что значит |
|---|---|
| `enabled` | `false` — выключить учёт опечаток |
| `threshold` | насколько слова должны быть похожи, 50–100 (меньше — терпимее к опечаткам, но больше ложных совпадений) |
| `minLength` | слова короче не сравниваются нечётко («пин» и «пинг» не спутаются) |
| `weight` | доля веса ключа при совпадении с опечаткой |

В отладке (`/отладка вкл`) такие совпадения видны: `(опечатка: рутокин≈рутокен)`.
При запуске бот пишет, чем считаются опечатки: `RapidFuzz` или `difflib`.

## База бесед (SQLite) и статистика

Все беседы дополнительно пишутся в базу `logs/cryptochat.db`: сессии, реплики (с номером выданного
вопроса и оценкой), отзывы «да/нет» и запросы, на которые бот не ответил сразу.
Включается в `config.json`: `"database": { "enabled": true, "path": "logs/cryptochat.db" }`.

```powershell
python run.py --stats
```

Покажет:
- сколько было бесед, сообщений, ответов и отзывов;
- какие ответы выдавались чаще всего и как их оценили;
- ответы с отзывом «не помогло» и запросы, по которым их получили, — что поправить в ответах и ключах;
- запросы, на которые бот не ответил сразу, — кандидаты в новые вопросы, ключи и синонимы.

Базу можно открыть и любой программой для SQLite (например, DB Browser for SQLite).

## Журнал бесед и отправка на почту

Каждая беседа получает **номер сессии** вида `20261028-084012-7f3a` (дата, время, 4 случайных символа).
Он печатается при запуске и по команде `/сессия`. Беседа сразу, реплика за репликой, пишется в файл
`logs/sessions/<номер>.txt` рядом с программой — журнал не теряется, даже если окно закрыли крестиком.
Включается в `config.json`: `"sessions": { "enabled": true, "path": "logs/sessions" }`.

Номер сессии также пишется в журналы отзывов и неотвеченных вопросов.

### Отправка журнала на почту

После выхода (`выход`, Ctrl+C) бот отправляет журнал беседы письмом: текст в теле письма и файл во вложении.
Если отправить не удалось (нет интернета, неверный пароль), журнал остаётся в папке и уходит при
следующем запуске. Беседы, где окно закрыли крестиком, тоже досылаются при следующем запуске
(через 12 часов после последней реплики — чтобы не отправить беседу, которая ещё идёт в другом окне).

1. Заведите ящик-отправитель и включите в нём доступ по SMTP и **пароль приложения**:
   - Яндекс: Настройки → Безопасность → Пароли приложений; сервер `smtp.yandex.ru`, порт 465, `ssl`;
   - Mail.ru: Безопасность → Пароли для внешних приложений; `smtp.mail.ru`, 465, `ssl`;
   - Gmail: нужна двухэтапная аутентификация, затем «Пароли приложений»; `smtp.gmail.com`, 465, `ssl`;
   - корпоративная почта: адрес сервера и порт даст ИТ-отдел (часто 587 и `starttls`).
2. Заполните блок `email` в `content/config.json`:
   ```json
   "email": {
     "enabled": true,
     "smtpHost": "smtp.yandex.ru",
     "smtpPort": 465,
     "security": "ssl",
     "username": "cryptochat-bot@yandex.ru",
     "from": "cryptochat-bot@yandex.ru",
     "to": ["кому@example.ru"]
   }
   ```
   `to` — один адрес или несколько: `["a@x.ru", "b@x.ru"]`.
3. Положите пароль приложения рядом с программой в файл `secrets.json` (образец — `secrets.example.json`):
   ```json
   { "smtpPassword": "пароль-приложения" }
   ```
   Файл исключён из Git. Вместо файла можно задать переменную окружения `CRYPTOCHAT_SMTP_PASSWORD`.
   **Не пишите пароль в config.json** — этот файл хранится в Git.
4. Проверьте: `python run.py --test-email` — должно прийти тестовое письмо.

Дослать неотправленные журналы вручную: `python run.py --send-pending`.

Беседы без единого сообщения не отправляются (`"sendEmpty": false`).

## Запуск

Из корня проекта (там, где лежат `run.py` и папка `content`):

```powershell
python run.py
```

Ключи:

| Ключ | Что делает |
|---|---|
| `--content <путь>` | взять базу из другой папки |
| `--validate` | проверить базу и выйти |
| `--selftest` | прогнать контрольные запросы (`content/acceptance.json`) и заголовки вопросов |
| `--compare` | сравнить стеммер и pymorphy3 на контрольных запросах |
| `--morphology <режим>` | `stemmer`, `pymorphy3` или `auto` вместо значения из config.json |
| `--test-email` | отправить тестовое письмо по настройкам `email` |
| `--send-pending` | дослать на почту журналы, которые не ушли раньше |
| `--stats` | статистика по базе бесед: частые ответы, отзывы, неотвеченные запросы |
| `--download-model` | скачать модель для поиска по смыслу в папку `models` |
| `--compare-semantic` | сравнить поиск с моделью и без неё |
| `--semantic-dump` | выгрузить оценки модели в `semantic_dump.json` для настройки |
| `--debug` | показывать, как бот ищет ответ (то же, что `/отладка вкл`) |
| `--version`, `--help` | версия и подсказка |

Команды в диалоге: `/помощь`, `/темы`, `/темы 1.2`, `/отладка вкл`, `/отладка выкл`, `/сессия`, `выход`.

## Тесты

```powershell
python -m unittest
```

Должно быть `OK`. Тесты проверяют стеммер, проверку базы, поиск, диалог и все контрольные запросы.
Тесты с настоящим pymorphy3 запускаются, только если он установлен (иначе помечены как skipped).

## Сборка CryptoChat.exe

```powershell
powershell -ExecutionPolicy Bypass -File build_exe.ps1
```

С поиском по смыслу (`.exe` вырастет до сотен мегабайт, папка `models` кладётся рядом; сборка с PyTorch
экспериментальная — проверьте её на чистом компьютере):

```powershell
powershell -ExecutionPolicy Bypass -File build_exe.ps1 -Semantic
```

Обычная сборка PyTorch не включает, даже если он установлен, а поиск по смыслу в ней выключается.

Скрипт установит pymorphy3, RapidFuzz и PyInstaller, прогонит тесты, соберёт `CryptoChat.exe` (со словарями
морфологии внутри) и положит его вместе с папкой
`content` в `publish\`. Для демонстрации передавайте папку `publish` целиком (например, в zip):
программа без папки `content` не запустится. Python на компьютере получателя не нужен.

```
  knowledge.py     чтение content/, проверка (V001–V016), база в памяти

  fuzzy.py         учёт опечаток: RapidFuzz или встроенный difflib
  semantic.py      поиск по смыслу: sentence-transformers (PyTorch), векторы вопросов
  storage.py       база бесед SQLite (logs/cryptochat.db) и отчёт --stats
  session.py       номер сессии, журнал беседы в logs/sessions/, поиск неотправленных
  mailer.py        отправка журнала на почту (SMTP), пароль из secrets.json
  cli.py           консоль, ключи запуска, самопроверка, журналы

tests/             тесты (unittest)
run.py             точка входа
build_exe.ps1      сборка CryptoChat.exe
secrets.example.json  образец файла с паролем почты (сам secrets.json в Git не попадает)
```

## Как править базу

1. Правьте файлы в `content\` (вопросы — `questions\*.json`, синонимы — `synonyms.json`, пороги — `config.json`).
2. `python run.py --validate` — проверка формата.
3. `python run.py --debug` — посмотреть оценки по проблемному запросу.
4. `python run.py --selftest` — убедиться, что ничего не сломалось.
5. Добавить исправленный запрос в `content\acceptance.json`, сохранить в Git.

Для собранного `.exe`: скопируйте `content` в `publish\content` или пересоберите.

## Как добавить продукт

Добавьте ветку в `content/taxonomy.json` (например `2.1 КриптоПро CSP`, `"kind": "product"`) и файл
`content/questions/2_csp.json` с вопросами. Код менять не нужно.
